01. Contexto Empresarial & El Problema en Producción

Impacto de filtros incompletos sobre registros con atributos opcionales

En sistemas corporativos (ERP, CRM o facturación), ciertos atributos de contacto son opcionales durante el alta inicial (ej. correo electrónico o teléfono secundario). Si las consultas de extracción no contemplan explícitamente los valores ausentes, el motor relacional descarta filas válidas.

Escenario de Omisión Involuntaria

Una consulta de notificación diseñada para identificar clientes cuyo correo no pertenece al dominio corporativo: 

SELECT cliente_id, nombre, email
FROM   clientes
WHERE  email NOT LIKE '%@empresa.com';

⚠️ Consecuencia: Las filas con email = NULL evalúan a UNKNOWN y son descartadas silenciosamente por la cláusula WHERE, omitiendo a los clientes sin correo registrado.

Tratamiento Defensivo con Normalización de Nulos

Uso explícito de COALESCE para sustituir valores ausentes antes de evaluar la condición o en la proyección: 

-- Tratamiento defensivo con COALESCE
SELECT cliente_id, nombre,
       COALESCE(email, 'SIN_EMAIL_REGISTRADO') AS email_seguro
FROM   clientes
WHERE  COALESCE(email, '') NOT LIKE '%@empresa.com';

✅ Resultado: Todos los registros son evaluados de manera predecible y consistente.

02. Cimiento Teórico Formal: La Lógica Trivalente en SQL

Fundamento matemático de Jan Łukasiewicz y Edgar F. Codd ante la presencia de valores NULL

A diferencia de los lenguajes de programación tradicionales (como Java, C# o Python) donde las comparaciones booleanas solo pueden ser Verdaderas (TRUE) o Falsas (FALSE), las bases de datos relacionales operan bajo una Lógica de Tres Valores (3-Valued Logic, 3VL):

1. TRUE (Verdadero)

La condición se satisface con absoluta certeza matemática y relacional.

2. FALSE (Falso)

La condición no se cumple con absoluta certeza matemática.

3. UNKNOWN (Desconocido)

La condición involucra un valor NULL, por lo que el motor relacional no puede determinar con certeza si es verdadero o falso.

La Regla de Oro sobre NULL: NULL NO es un valor; es un marcador de ausencia de dato o estado desconocido. Por esta razón matemática, dos nulos nunca pueden considerarse iguales. La expresión NULL = NULL NO evalúa a TRUE; evalúa estrictamente a UNKNOWN.

Las 3 Tablas de Verdad Oficiales de la Lógica Trivalente SQL

Estas son las matrices exactas con las que el optimizador y el motor de consultas resuelven cualquier expresión condicional:

Operador AND (Conjunción)

A \ BTRUEFALSEUNKNOWN
TRUE TRUE FALSE UNKNOWN
FALSE FALSE FALSE FALSE
UNKNOWN UNKNOWN FALSE UNKNOWN

Regla: FALSE es el elemento absorbente en AND (si uno es FALSE, todo es FALSE).

Operador OR (Disyunción)

A \ BTRUEFALSEUNKNOWN
TRUE TRUE TRUE TRUE
FALSE TRUE FALSE UNKNOWN
UNKNOWN TRUE UNKNOWN UNKNOWN

Regla: TRUE es el elemento dominante en OR (si uno es TRUE, todo es TRUE).

Operador NOT (Negación)

Valor ANOT AConsecuencia Didáctica
TRUEFALSESe invierte a falso.
FALSETRUESe invierte a verdadero.
UNKNOWNUNKNOWN¡Permanece UNKNOWN! Negar lo desconocido no lo hace conocido.
El Mecanismo de Aceptación Estricta de la Cláusula WHERE: El motor SQL filtra las tuplas bajo un filtro estricto: una fila es retornada ÚNICA Y EXCLUSIVAMENTE SI su predicado evalúa a TRUE. Si evalúa a FALSE o a UNKNOWN, la fila es descartada de forma silenciosa. Por eso, al evaluar WHERE email NOT LIKE '%@...' con un email nulo, la expresión evalúa a NOT UNKNOWN = UNKNOWN, y la fila es desechada.

03. Glosario de Palabras Clave

Sintaxis, comportamiento en el motor relacional y soporte multi-motor

COALESCE(...) Estándar ANSI SQL
SINTAXIS:
COALESCE(expresion_1, expresion_2, ..., expresion_n)
EJEMPLO:
-- Sustituye el valor NULL por un texto por defecto
SELECT cliente_id, nombre,
       COALESCE(email, 'SIN_CORREO_REGISTRADO') AS email_contacto
FROM   clientes;
  • Mecánica: Evalúa los argumentos en orden secuencial de izquierda a derecha y retorna el primer valor que no sea NULL. Si todos los argumentos son NULL, retorna NULL.
  • Cortocircuito (Short-Circuit): Se detiene inmediatamente al encontrar el primer argumento válido, sin evaluar las expresiones restantes (ahorrando tiempo de CPU y subconsultas).
  • Compatibilidad Multi-Motor: Es universal en DuckDB, PostgreSQL, Oracle, Microsoft SQL Server y MariaDB/MySQL.
IS NULL / IS NOT NULL Estándar ANSI SQL
SINTAXIS:
columna IS NULL
columna IS NOT NULL
EJEMPLO:
-- Filtra de forma estricta los clientes que no tienen teléfono registrado
SELECT cliente_id, nombre, ciudad
FROM   clientes
WHERE  telefono IS NULL;
  • Determinismo Booleano: Es el operador relacional estricto para comprobar ausencia de datos. Siempre evalúa a TRUE o FALSE (a diferencia de = NULL que resulta en UNKNOWN).
  • Anti-patrón de Producción: Nunca escribas columna = NULL o columna != NULL. Esas condiciones evalúan a UNKNOWN y son descartadas silenciosamente por la cláusula WHERE.
  • Indexación: PostgreSQL y SQL Server indexan valores nulos en árboles B-Tree; en Oracle tradicional, el árbol B-Tree omite filas donde todas las columnas indexadas son nulas.
LIKE / ILIKE ANSI & Extensiones
SINTAXIS:
columna [NOT] LIKE 'patron'     -- Sensible a mayúsculas/minúsculas (Estándar ANSI)
columna [NOT] ILIKE 'patron'    -- Insensible a mayúsculas (DuckDB y PostgreSQL)
EJEMPLO:
-- Busca clientes cuyo nombre contenga 'Tech' en cualquier posición y con cualquier combinación de mayúsculas
SELECT cliente_id, nombre, ciudad
FROM   clientes
WHERE  nombre ILIKE '%Tech%';
  • Comodín % (Porcentaje): Coincide con cero o más caracteres cualesquiera.
  • Comodín _ (Guion bajo): Coincide con exactamente un único carácter en dicha posición.
  • Sensibilidad a Mayúsculas: LIKE es sensible a mayúsculas en el estándar ANSI. ILIKE es la variante nativa insensible en DuckDB y PostgreSQL.
  • Otros Motores: En SQL Server depende de la colación (CI = Case Insensitive); en Oracle o MySQL se utiliza LOWER(columna) LIKE LOWER('patron') o expresiones regulares.
ESCAPE Estándar ANSI SQL
SINTAXIS:
columna LIKE 'patron_con_escape' ESCAPE 'caracter_escape'
EJEMPLO:
-- Busca productos que tengan un descuento literal del 15% (no como comodín)
SELECT factura_id, descripcion_item
FROM   facturacion
WHERE  descripcion_item LIKE '%15\%%' ESCAPE '\';
  • Mecánica: Neutraliza la función especial de los comodines % o _ para buscar el símbolo de forma literal en la base de datos.
  • Carácter de Escape: Cualquier carácter (frecuentemente \ o !) puede definirse como escape para preceder al símbolo buscado.
NULLIF(a, b) Estándar ANSI SQL
SINTAXIS:
NULLIF(expresion_1, expresion_2)
EJEMPLO:
-- Previene el error de división por cero convirtiendo 0 en NULL
SELECT venta_id, monto_total,
       monto_total / NULLIF(cuotas_pactadas, 0) AS valor_cuota_seguro
FROM   ventas;
  • Mecánica: Compara dos expresiones y retorna NULL si ambas son iguales; si son diferentes, retorna la primera expresión (expresion_1).
  • Uso Crítico: Previene excepciones fatales por división entre cero y permite normalizar cadenas de texto vacías en valores NULL (NULLIF(col, '')).
BETWEEN & IN Estándar ANSI SQL
SINTAXIS:
columna BETWEEN limite_inferior AND limite_superior
columna IN (valor_1, valor_2, ..., valor_n)
EJEMPLO:
-- Filtra clientes en un rango de fechas y pertenecientes a ciudades clave
SELECT cliente_id, nombre, ciudad, fecha_registro
FROM   clientes
WHERE  ciudad IN ('Bogotá', 'Medellín', 'Cali')
  AND  fecha_registro BETWEEN '2026-01-01' AND '2026-06-30';
  • BETWEEN: Evalúa un rango continuo inclusivo en ambos extremos ($limite\_inf \le x \le limite\_sup$).
  • IN: Evalúa pertenencia a una lista de valores discretos (equivalente a disyunciones con OR).
  • Precaución con NOT IN: Nunca utilices NOT IN ante subconsultas que contengan al menos un NULL, pues evaluará a UNKNOWN y descartará todos los registros (retornando 0 filas).

Consulta 2: Búsqueda de Descuentos con Porcentajes Literales usando ESCAPE

En este escenario, necesitamos encontrar productos o facturas con un descuento especial del 15% donde el signo % no debe comportarse como comodín: 

-- Búsqueda de cadenas que contienen literalmente el símbolo de porcentaje (%)
SELECT factura_id, cliente_id, descripcion_item, porcentaje_descuento
FROM   facturacion
WHERE  descripcion_item LIKE '%15\%%' ESCAPE '\';
Mecánica del Parser SQL: El motor lee la secuencia \%. Al estar configurado ESCAPE '\', despoja al % de su significado de comodín múltiple y busca el carácter ASCII 37 exacto precedido por el número 15.

07. Anti-Patrones y Consideraciones de Rendimiento

Prácticas que degradan el plan de ejecución o alteran el resultado lógico esperado

Anti-Patrón 1: Supresión de Índices B-Tree (Pérdida de SARGability) por Funciones en el WHERE

Al envolver una columna indexada dentro de una función (como LOWER(columna) o COALESCE(columna, ...)), el optimizador no puede utilizar la estructura ordenada del árbol y se ve forzado a ejecutar un Full Table Scan, evaluando la función fila por fila.

Consulta No SARGable (Table Scan) 
-- Inhabilita el índice sobre la columna email:
SELECT * 
FROM   clientes 
WHERE  COALESCE(email, '') = 'carlos@empresa.com';
Consulta SARGable (Index Seek / Scan) 
-- Permite al optimizador utilizar el índice:
SELECT * 
FROM   clientes 
WHERE  email = 'carlos@empresa.com' 
  AND  email IS NOT NULL;
Anti-Patrón 2: Búsquedas con Comodín Prefijo (%termino)

Un índice B-Tree estándar ordena las cadenas desde el primer carácter. Un filtro como LIKE 'Tech%' aprovecha un Index Range Scan eficiente. Por el contrario, LIKE '%Tech' requiere recorrer todas las páginas hoja del índice o de la tabla.

Recomendación en Grandes Volúmenes: Para búsquedas arbitrarias en textos extensos, implementar índices de texto completo (Full-Text Search, GIN o trigramas).
Anti-Patrón 3: Evaluación de NOT IN frente a Conjuntos con Valores NULL
Comportamiento Inesperado (0 Filas) 
-- Si un solo registro en jerarquia tiene padre_id NULL,
-- la comparación evalúa a UNKNOWN y retorna 0 filas:
SELECT * FROM clientes
WHERE  cliente_id NOT IN (
    SELECT padre_id FROM jerarquia
);
Alternativa Segura (NOT EXISTS) 
-- Robusto ante presencia de valores NULL:
SELECT c.* FROM clientes c
WHERE  NOT EXISTS (
    SELECT 1 FROM jerarquia j 
    WHERE  j.padre_id = c.cliente_id
);

Reto 1: Limpieza de Clientes para Campaña de Marketing

Se requiere generar una lista de clientes de la ciudad de 'Cali' o 'Medellín', asegurando que si no tienen teléfono registrado, se despliegue el texto 'SOLICITAR_NUMERO'. Además, se deben excluir aquellos clientes cuyo nombre contenga la palabra 'Gutiérrez' sin importar si fue escrita en mayúsculas o minúsculas.

Ver Solución Sugerida Comentada 
-- Solución Reto 1:
SELECT cliente_id, nombre, ciudad,
       COALESCE(telefono, 'SOLICITAR_NUMERO') AS telefono_gestion
FROM   clientes
WHERE  ciudad IN ('Cali', 'Medellín')
  AND  nombre NOT ILIKE '%Gutiérrez%';

Explicación: Usamos IN ('Cali', 'Medellín') para agrupar las ciudades, COALESCE para reemplazar los teléfonos nulos sin perder tuplas, y NOT ILIKE para excluir insensiblemente el apellido.

Reto 2: Cálculo Seguro de Saldo Promedio con Prevención de División por Cero

Escribe una consulta que calcule el saldo promedio por transacción (monto_total / transacciones_activas) garantizando que si transacciones_activas es igual a 0, la consulta no se rompa con un error de división por cero y entregue 0.00.

Ver Solución Sugerida Comentada 
-- Solución Reto 2 con NULLIF y COALESCE combinados:
SELECT cliente_id, monto_total, transacciones_activas,
       COALESCE(
           monto_total / NULLIF(transacciones_activas, 0), 
           0.00
       ) AS saldo_promedio_seguro
FROM   cartera_clientes;

Explicación: NULLIF(transacciones_activas, 0) transforma los ceros en NULL. Como cualquier número dividido entre NULL da NULL, la operación no arroja error. Luego, el COALESCE exterior captura ese NULL y lo convierte limpiamente en 0.00.
